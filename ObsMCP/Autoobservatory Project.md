# Autoobservatory Project

CLI astronomy toolkit (C++, `~/Autoobservatory FB`): an autoobservatory that drives a motorized AZ/ALT mount over serial, and a companion `planetarium` that draws an ASCII planisphere-style sky map.

## Binaries & tools

- **planetarium** — polar-projection ASCII sky dome (zenith center, N top / E right); flags: `lat lon --date --time --mag --fov DEG --center AZ,ALT --select NAME --follow --live [s] -h`. `--fov`/`--center` show a **limited view** — a circular field of `fov` degrees (must be smaller than a full sky, `0 < fov < 180`) centred on an azimuth/altitude; the map stays planisphere-oriented, only objects inside the field are drawn, and the `~` ring marks the field edge. Live mode redraws from the real clock every N s (default 10), arrow keys adjust mag limit (↑/↓ ±0.5) and refresh interval (←/→ ×2/÷2), `+`/`-` zoom and `w`/`a`/`s`/`d` pan the view (`0` resets to the full sky) on the fly, `f` follows the locked target so the field tracks it as the sky turns, the Pascal GUI additionally has `x`/`--window AZ1,AZ2,ALT1,ALT2` for a rectangular az/alt window (only objects between two azimuths — shortest arc, may straddle north — and two altitudes are drawn), `n`/`p` cycle an object cursor, `t` locks it as the mount target, `c` clears, `q` quits cleanly. `--select NAME` sets the target non-interactively (case-insensitive; also matches a unique prefix or substring, so `--select arctur` finds Arcturus, while an ambiguous query lists the candidates instead of guessing; canonical name written to `selected_target.txt`). Legend shows **Bayer designations for stars** (e.g. `Alpha_Lyr Vega`) and digit shorthand for clusters (`1 C Hyades`); all legend lines fit within 100 columns.
- **autoobservatory** — computes object positions, prints a table, or tracks a target with slew-rate-limited AZ/ALT output to Arduino (`-a`, `--deadzone` flags); `-h` prints usage, `--dry-run` validates everything and prints one `send: AZ:.. ALT:..` line (deadzone-gated like the real link) without opening any serial device. `--object NAME` resolves names through the same shared resolver as `planetarium --select` (`object_name.h`), so `--object arctur` finds Arcturus and an ambiguous name errors out. `--from-planetarium` reads the target selected in the live planetarium, so the two tools chain: pick an object on the dome, then track it
- **PasPlanetariumGUI** (`pas/`, Free Pascal / Lazarus LCL Form app) — canvas-based port of the live planetarium with mouse-over tooltips, clickable legend, and a mag-limit trackbar. Same ephemeris math via the `astrop.pas` unit. Build with `make gui`, run `./pas/PasPlanetariumGUI [lat lon] [--date YYYY-MM-DD] [--time HH:MM[:SS]]` — UTC everywhere, `--date`/`--time` replay a fixed instant (title shows "FIXED TIME"). Legend shows Bayer designations for stars (8pt font, variable-width names, fits in 240px legend column). Details: [[Pascal Planetarium GUI]]
- **tools/ephcheck** — self-check comparing model positions/magnitudes against JPL/theskylive references at **two epochs** (catches element-rate errors like the Saturn dM bug)
- **tools/ephcheck_pas** — same two-epoch reference table run against the Pascal `astrop.pas` unit (`make check-gui`); caught a missing Mercury/Venus phase correction in the port
- **tools/hgcheck.cpp + pas/hgcheck_pas.lpr** — frozen-value unit test pinning the IAU H-G phase function (`HGPhase()`) against a 19-case (G, phase angle, Φ) table, run through BOTH the C++ and Pascal implementations by `make check-hg`; the ports cannot diverge without failing one of them
- **tools/viewcheck.cpp + pas/viewcheck_pas.lpr** — sky-view projection check (`make check-view`): pins the limited-view azimuthal-equidistant projection in `sky_view.h` / `astrop.pas`. Its first case proves the default full-sky view reproduces the old polar projection EXACTLY on a grid of az/alt (so the full-sky map cannot drift), then checks N/E/S/W orientation, linear zoom scaling, out-of-field rejection and the `--fov`/`--center` validation rules — in BOTH languages
- **tools/objectname_check.cpp** — unit check for `object_name.h` against a small synthetic catalog (no CSVs): exact, unique prefix, unique substring, exact-beats-ambiguous-prefix, ambiguous, and unknown, pinning the matching contract independently of catalog edits (`make check-name`)
- **tools/namecheck.sh / namecheck_gui.sh** — assert `--select`/`--object` resolves an exact name and a unique fuzzy one and fails (non-zero, listing candidates) on an ambiguous query; the first runs the same cases through both C++ tools, planetarium and autoobservatory (`make check-select`), the second through the Pascal GUI (`make check-select-gui`, which skips cleanly when `DISPLAY` is unset)
- **tools/clicheck.sh** — argument-handling regression net enforcing the exit-code convention: usage errors (bad numbers, unknown flags, impossible positions, missing required args, malformed/out-of-range `--date`/`--time`) exit 2, runtime errors (unresolvable object) exit 1, `-h` and `--dry-run` exit 0 (`make check-cli`)
- **tools/catcheck.cpp** — star-catalog sanity check (`make check-cat`): every `celestial_objects.csv` row parses with RA ∈ [0,24) h and Dec ∈ [−90,90]°, names are unique, stars brighter than mag 0 carry a Bayer designation, every non-empty Bayer validates as `<Greek letter>_<3-letter IAU abbreviation>` against the full 88-constellation list (catches typos like `Alpha_Orion` that would silently render as-is in the legend), the reader's object count matches the file's valid-row count, and every name resolves to itself through the shared `object_name.h` resolver against the full 922-name star+planet pool (catches prefix-shadowing between entries)
- **Makefile** — `make` (C++ binaries), `make gui` (Pascal GUI), `make check` (C++ ephcheck + sky-view projection check + name-resolution unit check + CLI-argument check + `--select`/`--object` end-to-end checks + H-G phase unit test + catalog sanity check + Pascal self-check), `make check-gui` (Pascal self-check only), `make check-hg` (H-G phase function only), `make check-cat` (catalog sanity only), `make check-view` (sky-view projection only), `make clean`

## Data files

- **planetary_objects.csv** — orbital elements for 9 main-belt asteroids (Vesta, Pallas, Juno, Hebe, Iris, Flora, Hygiea, Eunomia, Psyche) and 11 distant small bodies (IAU dwarf planets Ceres, Pluto, Haumea, Makemake, Eris plus TNOs Orcus, Quaoar, Gonggong, Ixion, Varuna, Sedna), J2000 epoch, documented header with unit/rate semantics and the Kepler's-third-law consistency rule for mean motion. Earth excluded (observer); Moon computed by a dedicated model. The asteroids/TNOs use JPL Horizons osculating elements at epoch 2026-06-09 with M0 back-propagated to J2000 and dM = Horizons mean motion (same recipe as Ceres); the 14th column holds the absolute magnitude `H` and the 15th the IAU H-G phase slope `G`, both from JPL Horizons, so minor-body brightness runs through the H-G phase function. Pluto is the one exception: its H stays an effective calibrated value because its orbit is the SBDB solution back-propagated rather than Horizons at J2000.
  **The eight major planets' CSV rows are retained for provenance and magnitude zero-points only — both engines skip them.** The planets are computed from VSOP87 series, not from these elements. The Kepler path serves Pluto, Ceres, the asteroids and the TNOs; see [[Astronomy Math Reference#VSOP87 truncated series]].
- **celestial_objects.csv** — 894 stars and deep-sky objects (name, RA, Dec, mag, **Bayer designation**) in 10 columns. The 10th column `bayer` holds the Bayer designation for stars (e.g. `Alpha_UMi` for Polaris, `Alpha_Ori` for Betelgeuse, `Beta_Ori` for Rigel, `Alpha_Boo` for Arcturus, `Alpha_Cen` for Rigil Kentaurus) in `Letter_Constellation` format using 3-letter IAU constellation abbreviations; clusters, nebulae, and galaxies leave it blank. **434 Bayer-designated stars** — the original curated naked-eye set (full Big Dipper, Cassiopeia, the southern showpieces Alpha Centauri/Canopus/Achernar, Eta Carinae) plus every Bayer star brighter than V = 4.0 from the **HYG v4.1** database, named by proper name where one exists and otherwise by `<Greek> <genitive constellation>` (e.g. `Epsilon Phoenicis`, `Lambda Andromedae`). **460 clusters and nebulae** — the original curated set plus the rest of the **Messier** catalogue and all clusters/nebulae fainter than magnitude 10 (open clusters, globulars, planetary/emission/reflection/dark nebulae, supernova remnants, HII regions and stellar associations) from **OpenNGC**, named `M<n>`, `NGC <n>` or `IC <n>` with a common name in parentheses where one exists (e.g. `NGC 7662 (Copeland's Blue Snowball)`). Galaxies are intentionally excluded (the request was clusters and nebulae); the original Magellanic Clouds / M33 / Andromeda rows remain. Extra rows were generated from HYG v4.1 and OpenNGC (both CC BY-SA 4.0) with a throwaway script, converted to the catalog schema (J2000 RA/Dec, V magnitude, Bayer). Both the C++ `planetarium` and Pascal `PasPlanetariumGUI` show Bayer designations in their legends for stars and digit shorthand for clusters. Note: this file allows **no comment lines** — `CelestialObjectReader` skips only the header and would `std::stod` a `#` line and throw.

## Architecture

The CSV→engine seam is one function: `ComputeRAandDecFromElements(PCSVElements, magBase, jd)`. Parsing (CSV) and math (orbit engine) never mix. `GetPlanetaryObjects(jd)` returns a flat `PlanetaryObject` list consumed by all five programs (autoobservatory, planetarium, calibrate, ephcheck, PasPlanetariumGUI) — dwarf-planet support and the regression net came free everywhere. **Exit-code convention (all binaries): 0 success, 1 runtime error (serial device, missing files, unresolvable object), 2 usage error (bad number, unknown/incomplete option, impossible lat/lon, missing required argument)** — documented in each tool's `-h` and enforced by `tools/clicheck.sh`. The **view seam** is `sky_view.h`, mirrored by `TSkyView`/`ProjectSky` in `astrop.pas`: `ProjectSky(view, az, alt, u, v)` returns false for positions outside the field, and at the default zenith/180° view it reduces exactly to the original polar formula, so the full-sky map is unchanged. The **name-resolution seam** is likewise one module: `object_name.h` (C++), mirrored by `ResolveName` in `astrop.pas`, used by `planetarium --select`, `autoobservatory --object`/`--from-planetarium`, and the GUI — exact / unique-prefix / unique-substring matching and ambiguity handling are identical everywhere. The same goes for strict `--date`/`--time` parsing: `cli_parse.h` and its `astrop.pas` port (`ParseDateArg`/`ParseTimeArg`) reject the same malformed inputs (Feb 30, hour 25, wrong separators) with identical messages in the terminal tools and the GUI. Argument handling is shared too: `cli_parse.h` gives all three binaries the same numeric parsing (a clean error and exit 2 instead of an abort), an observer lat/lon range check, rejection of unknown or incomplete options (negative coordinates like "-33.9" still parse as positions), and strict `--date YYYY-MM-DD` / `--time HH:MM[:SS]` parsing — a malformed or impossible date/time (Feb 30, hour 25, wrong separator) is a usage error (exit 2) instead of a silently wrong sky map; leap days are accepted. Positional lat/lon also accept **DEG MIN SEC HEMI** form (`45 30 15 N 9 12 30 E`) alongside decimal degrees — D/DM/DMS with fractional parts, hemisphere letter sets the sign (S/W negative), minutes/seconds must be in [0,60); a bare `45 30` still means decimal lat 45 lon 30 because minutes require a trailing hemisphere letter.

## Accuracy model (per-object)

1. Keplerian mean elements from CSV → heliocentric vector
2. **Light-time correction** (iterate at `jd − dist/173.15` days)
3. **IAU 2006 precession** (ζ/z/θ matrix, J2000 → true-of-date)
4. **Annual aberration** (k·v_earth added to geocentric vector)

Result: planets 0.15–0.45 arcmin avg of true ephemeris (arcsecond-class) — the 8 major planets run on **truncated VSOP87 series** (generated tables, mirrored C++/Pascal; the 2026-10 audit first found Neptune ~4° off and Saturn ~26′ off with mean elements, fixed them with Horizons osculating elements, then replaced them with VSOP87). Pluto, Ceres, the asteroids and TNOs stay on CSV Keplerian elements (Horizons osculating, M0 back-propagated to J2000; Pluto SBDB); Haumea/Makemake/Eris H-G magnitudes are true absolute magnitudes. Details and the measured error table: [[Ephemeris Accuracy Verification]].

## Moon model

Schlyter elements (epoch JD 2451543.5 — **not** J2000 noon, this was a 26° bug) + 12 longitude / 5 latitude / 2 distance perturbation terms (evection, variation, yearly equation…). Self-consistent: D and F derived from the same element set. **No precession applied** — Schlyter outputs equinox-of-date already. Result: **0.8 arcmin** vs JPL Horizons. Magnitude is a phase approximation (~0.5 mag off).

## Planetarium extras

**Target hand-off to the mount.** In live mode `n`/`p` (or Tab) cycle an object cursor, `t` locks the highlighted object as the target, `c` clears it. The locked name is written to `selected_target.txt` (single line, same directory), and `./autoobservatory <lat> <lon> --from-planetarium -a --serial DEV` reads it — so selecting an object on the dome and tracking it are two commands. The Pascal GUI does the same on click. `--object NAME` works for direct selection with the same fuzzy matching, `--target-file FILE` overrides the hand-off path.

**Live tracking panel.** While a target is locked, the planetarium prints two lines above the dome:

```
tracking: Arcturus              az  269.46  alt   28.21
mount:    AZ  269.52  ALT   28.44   dAZ  +0.06  dALT  +0.23  sep 0.24 deg  ON TARGET   (2s ago)
```

The left column is the object's live position this frame; the right is the mount's **last position actually sent**, published by the autoobservatory to `mount_status.txt` (`AZ:<deg> ALT:<deg> TARGET:<name> T:<epoch>`, rewritten only when a serial line passes the deadzone gate). `sep` is the true angular separation (az/alt cosine formula, not a Euclidean approximation), flagged `ON TARGET` under 0.5°, and the age shows how stale the mount data is — useful for spotting a stalled mount or a silent serial link. The Pascal GUI shows the same line under its header. `make clean` removes both hand-off files.

**Limited views.** `--fov DEG --center AZ,ALT` (or the live `+`/`-`/`w`/`a`/`s`/`d`/`0` keys) zoom the map onto one part of the sky: a circular field of `fov` degrees (strictly smaller than a full sky, so `0 < fov < 180`; omitting it keeps the full sky), centred on the given azimuth/altitude. The projection is in [[Astronomy Math Reference]]; the header's `view:` line reports the current centre and field size. The Pascal GUI takes the same flags and keys. Only objects inside the field are drawn and listed, and the horizon is projected as a curve so it is clipped correctly.

**Follow mode.** `--follow` (or the live `f` key) keeps a limited view centred on the **locked target**: the view centre is rewritten to the target's az/alt every frame, so a `--fov 24` field on Vega tracks it across the sky. The target is whatever `--select NAME` or the live `n`/`p`+`t` picker locked. It composes with the view seam rather than changing it — the projection is untouched, only `centerAz`/`centerAlt` move. Panning (`w`/`a`/`s`/`d`) or `0` is a manual override that drops follow, while `+`/`-` keeps tracking. The header's `view:` line reports `follow: on (TARGET)`/`follow: off`; the Pascal GUI mirrors it with a `Follow: Boolean` field applied in `DrawDome` before drawing.

Moon rise/set (5-min brute-force scan) and phase names (elongation-based waxing/waning + illumination buckets); verified across a full September 2026 lunation. Sun reporting: altitude + twilight state (day/civil/nautical/astronomical/night) and sunrise/sunset + civil twilight window in the header, `@` sun marker on the dome when up — same 5-min scan generalized to any altitude threshold (−0.833° rise/set, −6° civil). All of this is shared by the C++ CLI and the Pascal GUI.

## Hard-won lessons

- Schlyter Moon epoch is 1999-12-31 0h UT, mixing epochs cost 26°
- Perturbation terms must come from the same element system (Schlyter vs Meeus don't mix)
- Positional CSV parsing is the fragile seam — guarded only by `make check`
- Magnitude zero-points must be calibrated, not guessed (Ceres showed mag 3 instead of 8.75). For minor bodies (`G > 0`) the magnitude column is the **absolute magnitude H** and the model applies the H-G phase function — the distance-only `H + 5·log10(r·d)` form is only valid at opposition, so an off-opposition asteroid would otherwise be too bright
- Trig in the H-G model is **radian-only**: `tan(α/2)` must take the half-angle in radians (tan(60°) ≈ 1.73, not tan(60 rad)). The first hand-computed reference table for the H-G unit test used degrees and was wrong by up to 0.28 Φ — the frozen-value test caught all 14 cases before anything shipped. If a phase function looks "too dark" far from opposition, check the angle units first
- Follow mode must recentre the view *before* the frame is drawn, but the target's position lives in the sky vector built *during* the frame — so the planetarium builds catalog positions first and draws second. Reusing the already-computed `sky` list also means a target fainter than the mag limit (or currently outside the field) still steers the view, instead of falling into the "not in catalog" fallback used by the tracking panel
- The field-edge test in the limited-view projection needs a hair of tolerance: with a bare `theta > halfField`, `cos()` rounding put the horizon (`alt = 0`) a couple of ULP *past* the full-sky field for half the azimuths, so the horizon ring and the cardinal points silently disappeared from the default map. `+1e-12` rad fixed it — and the grid equivalence test in `tools/viewcheck.cpp` flags exactly this class of regression
