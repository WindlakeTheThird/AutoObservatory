# Ephemeris Accuracy Verification

How the [[Autoobservatory Project]] proves its positions are right, and how regressions are caught.

## ephcheck (tools/ephcheck.cpp)

Runs `make check`. Compares `GetPlanetaryObjects()` output against reference tables at **two epochs** — 2026-09-23 (calibration, tol ~0.35–0.5°) and 2027-03-23 (tol ~0.5–0.6°). 9 objects × 2 epochs + Moon = 23 checks (Mercury and Mars added as the fastest movers — best rate-error detectors). Exits 1 on failure so it can gate builds.

### Why two epochs

A single epoch cannot distinguish "right position, wrong mean motion." Any dM error of k deg/day shows as ~182.6·k degrees of drift between epochs. Proven by re-injecting Saturn's old bad dM: both epochs FAIL, restore → all pass.

### Moon check

Single-epoch (2026-09-23) vs JPL Horizons geocentric apparent, tolerance 8′. The Moon drifts ~13°/day so a second epoch re-tests the same elements at a random phase — no added value.

## Reference sources

- JPL Horizons API (authoritative, geocentric apparent RA/Dec)
- JPL SBDB API (osculating elements for asteroids/dwarf planets)
- theskylive / in-the-sky (apparent magnitudes)
- Schlyter (stjarnhimlen.se) for planetary mean elements and the lunar model

## Reference values live with the model

Epoch-2 references are model extrapolations with exact mean motions, not external ephemeris. When re-calibrating (element refresh, model change), regenerate both tables from the harness, then spot-check epoch 1 against external sources.

## Known accuracy ceiling

| Object class | Residual vs true ephemeris |
|---|---|
| Planets (VSOP87) | 0.15–0.45′ avg, ≤0.75′ max (Venus spikes to 2.1′ for ~1 day at inferior conjunction) |
| Pluto (Keplerian, VSOP87 has no Pluto) | ~11′ |
| Asteroids/TNOs (osculating Keplerian) | 0.2–0.3° |
| Moon | 0.8′ |

Good enough for hobby-mount pointing; not for astrometry.

## 2026-10 VSOP87 upgrade (arcsecond-class planets)

The 8 major planets no longer use CSV mean elements. `planetary_objects.h` (C++) and `astrop.pas` (Pascal) now evaluate **truncated VSOP87 series** generated by `tools/vsop87_gen.py` from the PyMeeus VSOP87 tables (LGPL; keep the attribution in the generated files):

- `vsop87_trunc.h` (C++) / `pas/vsop87_trunc.inc` (Pascal): flat A,B,C term arrays (L/B in 1e-8 rad, R in 1e-8 AU), per-term t-power bytes, and a layout table. Terms with amplitude < 1 (≈0.2″) dropped — regeneration with a smaller limit buys nothing measurable.
- Pipeline (both languages, in lockstep): heliocentric ecliptic L/B/R → **FK5 correction** (Meeus ch. 32, <0.1″) → geocentric vector with 3-iteration light time → **annual aberration** (Earth velocity by central difference over 0.01 d, k=0.0057755 d/AU; the old model's 0.5 d difference applied only half the aberration — fixed) → **mean obliquity of date** rotation. **No precession step**: VSOP87 series are already referred to the mean equinox of date (applying PrecessJ2000ToDate was a 0.45° double-precession bug caught by the sweep).
- CSV planet rows are skipped by both engines (kept for provenance/zero-points); Pluto, Ceres and the asteroids/TNOs still use the CSV Keplerian path.
- ephcheck reference tables for the 7 planets are now **true JPL Horizons values** (apparent RA/Dec + APmag, fetched 2026-10), tol 0.03° = 72″; magnitude tolerances reflect the Schlyter phase model's large-phase divergence from Horizons (Mercury ~1.7 mag worst; positions unaffected).

**Measured vs Horizons (48 monthly epochs 2024–2027, tools/ephaudit.py):** Mercury 0.35′/0.74′ avg/max, Venus 0.40′/2.08′, Mars 0.16′/0.49′, Jupiter 0.15′/0.33′, Saturn 0.20′/0.43′, Uranus 0.18′/0.30′, Neptune 0.23′/0.50′. The remaining ~10–25″ is nutation (up to 17″, not modelled) + frame truncation. Venus's one-day 2.1′ spike at inferior conjunction is a conjunction-geometry artefact on an unobservable target. Residual ~11′ on Pluto is the Keplerian floor — VSOP87 does not cover Pluto.

Gotchas for future edits: the flat term array is level-ordered ascending (evaluate each level with t^level, no Horner over mixed levels); the power byte array is per-term and parallel to each series' range; planet index 2 is Earth — skip it when emitting objects (geocentric Earth is degenerate).

## 2026-10 planet accuracy audit (tools/ephaudit.py)

`tools/ephaudit.py` compares the model against **JPL Horizons geocentric apparent RA/Dec at 48 monthly epochs, 2024-01 … 2027-12** (one Horizons OBSERVER ephemeris per planet, quantities=2, DEG/ICRF/UT). `tools/ephdump.cpp` dumps the model side. This catches what the two-epoch ephcheck cannot: it is fully independent of the model.

**Findings against the old Schlyter mean elements:**

- **Neptune was broken: ~232′ (3.9°) constant error** — a mean-longitude/zero-point inconsistency between its CSV row and the true orbit, not just the mean-elements floor. No regression test had covered it (it was absent from ephcheck).
- **Saturn ~26′ avg (rising to 32′ by 2027)** — stale element rates.
- Mars 15′, Uranus 18.5′, Mercury 13.5′, Venus 14′, Jupiter 11′, Pluto 11.5′.

**Fix:** all 8 planets regenerated from JPL Horizons osculating elements (epoch 2026-06-09, ecliptic, heliocenter; M0 back-propagated to J2000, dM = Horizons mean motion) — the same recipe the asteroids/TNOs already use. Averaging elements over several epochs was tried and rejected (no improvement; single 2026-06-09 epoch fits 2024–2027 best).

**After the fix (avg / max over 48 epochs):** Mercury 13.5′/21′, Venus 14.1′/29′, Mars 11.8′/19′, Jupiter 9.8′/19′, Saturn 16.7′/18′, Uranus 9.7′/11′, **Neptune 17.3′/19′** (was 232′!), Pluto 11′/12′. Saturn halved; all within the documented floor.

Residual ~10–30′ is the irreducible cost of a single Keplerian osculating orbit vs the real perturbed orbit (great for Saturn/Venus near their epochs; Mercury/Venus residuals concentrate near elongation extremes). Fixing that needs perturbation theory or VSOP87 — a model change, not a data change.

**Side fix found by the audit:** the Pascal mirror selected the Mercury/Venus phase correction by matching semi-major axis (`a = 0.387098/0.723330`); the refreshed a values silently disabled it (mag off by 1.6). Now selects by object name, matching C++.
